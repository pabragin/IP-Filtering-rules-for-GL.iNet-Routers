# Правила IP-фильтрации для роутеров GL.iNet

Единый автообновляемый список для раздельной VPN-маршрутизации на роутерах GL.iNet
(проверено на Flint 2 / GL-MT6000): **все российские подсети IPv4/IPv6 + домены
нужных сервисов на иностранном хостинге** — в одном файле `filter.txt`, который
роутер забирает по Subscription URL.

Задача: часть трафика (российские сервисы, банки, Госуслуги, Steam и т.д.) пустить
одним маршрутом, весь остальной — другим.

## Файлы репозитория

| Файл | Назначение |
|---|---|
| `filter.txt` | **Итоговый список** для Subscription URL: домены + IPv4-подсети + IPv6-подсети, по одной записи на строку |
| `report.md` | Отчёт последней сборки: какие домены покрыты подсетями и исключены, какие оставлены |
| `data/domains.txt` | Исходный список доменов — **редактируется вручную**, сюда добавляются новые сервисы |
| `data/custom-subnets.txt` | Ручные подсети в дополнение к российским (например, 17.0.0.0/8 — Apple) |
| `scripts/build.py` | Скрипт сборки |
| `.github/workflows/build.yml` | Автоматическая пересборка на GitHub Actions |

## Как это работает

### 1. Откуда берутся российские подсети

Подсети собираются из **двух независимых источников** — по отдельности каждый
из них неполон.

**Источник 1 — делегации RIR** ([ipverse/country-ip-blocks](https://github.com/ipverse/country-ip-blocks)):
агрегированные данные RIPE о блоках, у которых `inetnum` помечен `country: RU`
(~8 700 подсетей IPv4, ~2 200 IPv6), обновляются ежедневно.

**Источник 2 — анонсы российских автономных систем:** список AS с `country: RU`
берётся из [RIPEstat](https://stat.ripe.net) (~5 800 AS), затем из полной
таблицы BGP [bgp.tools](https://bgp.tools) отбираются префиксы, которые эти AS
анонсируют.

Второй источник нужен потому, что у одной организации записи `inetnum` и
`aut-num` могут иметь **разную страну**. Живой пример: сайты правительства
Санкт-Петербурга (`gov.spb.ru`, `gu.spb.ru`, `mfc.spb.ru`, `petersburgedu.ru`)
живут на `46.243.177.0/24`. Блок записан в RIPE на нидерландское юрлицо
LeaderTelecom B.V., поэтому в списках по делегациям его нет — хотя сервер стоит
в Петербурге. Но анонсирует его `AS203725` (СПб ГУП «ИАЦ») с `country: RU`,
и второй источник его находит.

Обратный случай тоже есть: `51.250.128.0/17` (Yandex Cloud) помечен RU в RIR,
но публично в BGP не анонсируется — его даёт только первый источник. Поэтому
источники объединяются, а не заменяют друг друга: вместе они дают ~10 600
подсетей IPv4 вместо 8 700.

Побочный эффект объединения: в список попадают блоки, анонсируемые российскими
AS, но принадлежащие по RIR другим регионам (например, `181.202.0.0/16` из
LACNIC) — около 1,2 млн адресов. Для раздельной маршрутизации это безвредно:
такой трафик просто пойдёт «российским» маршрутом.

Если bgp.tools или RIPEstat недоступны, сборка не падает: она продолжается на
одном источнике и помечает это в `report.md`.

К подсетям добавляются записи из `data/custom-subnets.txt` (иностранные
диапазоны, которые тоже должны попадать под правило — например, вся сеть Apple,
игровые серверы Steam и Blizzard). Всё вместе агрегируется: вложенные и соседние
подсети схлопываются, дублей не остаётся.

### 2. Зачем нужна проверка доменов

Список доменов в `data/domains.txt` — исходный. Держать в правилах роутера и домен,
и подсеть, в которую он входит, бессмысленно, поэтому скрипт для каждого домена
запрашивает адреса (A- и AAAA-записи) самого домена **и его `www`-поддомена**,
после чего проверяет:

- **Все адреса внутри собранных подсетей** → домен *покрыт* и в `filter.txt`
  не пишется.

  `www` проверяется отдельно не зря: у части сервисов апекс живёт на своих
  адресах, а `www` отдаётся сторонним CDN. Так, `apple.com` резолвится в
  `17.0.0.0/8` (эта сеть есть в подсетях), а `www.apple.com` — в адрес Akamai
  вне её. Роутер матчит домены по суффиксу, поэтому запись апекса покрывает и
  поддомены; исключать её можно, только когда `www` тоже внутри подсетей.
- **Хотя бы один адрес снаружи** → домен остаётся в `filter.txt`. Это сервисы на
  иностранном хостинге и CDN: Steam, Plex, Google-сервисы, bitrix24.com и т.п.
  Подсетями их не покрыть (CDN отдаёт разные адреса), поэтому роутер будет
  матчить их по DNS-имени.
- **Домен не резолвится** (например, чисто CDN-домены вроде `steamcontent.com`,
  у которых нет записи на апексе) → домен на всякий случай остаётся в списке.

Результат каждой проверки записывается в `report.md` — по нему видно, почему
каждый домен попал или не попал в итоговый файл.

### 3. Что получается на выходе

`filter.txt` — один плоский файл (~11 000 строк), без комментариев, по одной
записи на строку:

```
steamcommunity.com     ← домены (иностранный хостинг)
plex.tv
...
2.56.24.0/22           ← российские IPv4-подсети + ручные
17.0.0.0/8
...
2001:640::/32          ← российские IPv6-подсети
...
```

Именно такой формат понимает GL.iNet: домены и подсети можно смешивать в одном
файле подписки.

### 4. Автообновление

GitHub Actions (`.github/workflows/build.yml`) пересобирает `filter.txt`:

- **ежедневно** по расписанию (03:17 UTC) — подтягиваются свежие российские подсети;
- **при каждом изменении** `data/` или `scripts/` — то есть достаточно добавить
  домен в `data/domains.txt` и запушить;
- вручную через кнопку **Run workflow** во вкладке Actions.

Если список изменился, workflow сам коммитит новые `filter.txt` и `report.md`.
Роутер, в свою очередь, периодически перекачивает файл по Subscription URL.

## Настройка на роутере GL.iNet

1. Админ-панель → **VPN → VPN Dashboard** — включите VPN-клиент (WireGuard/OpenVPN).
2. **VPN → Proxy Mode → Based on the Target Domain or IP** (в старых прошивках —
   VPN Policies → Domain/IP).
3. В поле **Subscription URL** вставьте raw-ссылку на `filter.txt`:

   ```
   https://raw.githubusercontent.com/<логин>/<репозиторий>/main/filter.txt
   ```

4. Выберите, что делать с совпавшим трафиком — пускать **через VPN** или
   **напрямую** (остальной трафик пойдёт противоположным путём), и задайте
   период автообновления подписки.

## Как добавить новый сервис

1. Допишите домен в `data/domains.txt` (или подсеть в `data/custom-subnets.txt`).
   Домены, которые заведомо хостятся в России, добавлять не нужно — они и так
   покрыты подсетями. В сентябре 2026 такие 105 доменов из списка убраны, чтобы
   не резолвить их при каждой сборке; при необходимости их можно поднять из
   истории git.
2. Запушьте — GitHub Actions пересоберёт `filter.txt` автоматически.
3. Либо пересоберите локально:

   ```sh
   python3 scripts/build.py
   ```

   Нужен только Python 3.10+ и доступ в интернет.

## Нюансы

- Домен исключается из списка по результату резолва с машины сборки. У больших
  сервисов DNS геозависим, но российские сервисы отдают российские адреса из
  любой точки мира, так что практический риск минимален. Проверить всегда можно
  по `report.md`.
- ~11 000 записей — нормальный объём для GL.iNet (dnsmasq + ipset/nftables),
  это меньше типичных списков antifilter.
- Если VPN-туннель не поддерживает IPv6, IPv6-подсети в списке просто не будут
  использоваться — вреда от них нет.
